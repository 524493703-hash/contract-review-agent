# 合同审核流程 V2

## 目标

审核结果必须同时满足三个条件：问题判断有依据、重要问题不因模型随机性遗漏、每条结论能够回到输入文件的页码和条款号。公司标准条款、客户合同事实和现行法规不得混为同一类知识。

## 流程

1. 识别合同类型、我方角色、交易场景和文件完整性。
2. 按原始文档顺序解析段落、表格、附件和修订，不把表格统一追加到正文末尾。
3. 为每个文本块记录 `source_file`、`page_no`、`page_method`、`start_offset`、`end_offset` 和块类型。
4. 选择由合同类型、我方角色、设备类型和公司基准版本组合而成的 Playbook。
5. 对每个 Focused Check 独立检索。客户合同条款号不得与公司基准条款号直接等同。
6. 候选条款必须命中该 Check 的主题锚点；禁止用“通知、变更、电子邮件”等通用词单独作为相关证据。
7. 必需槽位必须由同一条连贯条款满足，禁止跨多个无关候选拼接成 `MET`。
8. 确定性规则先判断明确的不利表述、金额阈值、日期、单位、算术和跨条款冲突。
9. DeepSeek 只在该 Check 已召回的候选 offset 内做语义裁决。确定性不利规则命中后，模型不得改写状态或替换不利证据。
10. 输出 `MET / UNMET / PARTIAL / NOT_MENTIONED`。解析失败或文件包不完整时使用技术状态 `UNVERIFIABLE`，不得伪装成条款缺失。
11. 只有涉及法律效力、法定义务或强制性规范的问题才进入法律 RAG。
12. 每条结论保存合同证据、公司基准依据、法规依据、风险原因、修改策略和人工确认状态。

## 三类知识必须分层

### 客户合同事实层

这是本次审核的唯一事实来源。证据必须逐字存在于上传文件，并绑定文件哈希、版本、页码、条款号和字符 offset。

### 公司 Playbook 与基准条款层

林德设备租赁一般性条款存入 `company_baseline` 命名空间，并拆成：

- 文档版本记录：文件名、版本、生效日、文件哈希和文本哈希；
- `ClauseNode`：按 1.1、1.2 等条款号切分；
- `ClauseAtom`：把义务、权利、条件、例外、后果和数值拆成原子命题；
- `ClauseLink`：保存引用、例外、冲突和依赖关系；
- `CheckBaselineMap`：明确每个 Focused Check 对应哪些标准条款和原子命题。

公司标准是商业立场，不得在报告中称为法律。客户合同未纳入该一般性条款时，它只能作为比对基准，不能作为客户已经同意的合同内容。

### 法律法规层

法规应当入库，但必须使用独立的 `legal_authorities` 表或 `legal_rag` 命名空间，不能与公司条款共用权威等级。每条法规至少保存：

- 制定机关、标题、文号和具体条款号；
- 条文原文和适用摘要；
- 司法辖区、生效日、失效日和状态；
- 官方来源 URL、内容哈希和抓取时间；
- 关键词及适用的 Focused Check；
- 本次审核采用的 `legal_as_of_date`。

法律 RAG 只解释法律风险，不直接替代合同事实判断。例如，系统先确定合同存在“放弃请求调低违约金”的原文，再检索《民法典》第五百八十五条和合同编通则司法解释；不得先检索法规，再推测合同中存在该条款。

## 防遗漏机制

Focused Checks 负责逐主题覆盖，公司基准负责标准偏离，合同完整性检查负责跨条款和表格异常，自由模型审查只负责补充未建模风险。四条路径的结果可以合并去重，但任何一路都不能覆盖另一路的原始证据。

合同完整性检查至少包括：

- 未税价、税率和含税价的算术一致性；
- 日期有效性和合同是否在审核基准日届满；
- 金额、比例、期限和技术单位的数量级异常；
- 正文、附件、订单及平台条款之间的冲突；
- 同一事件的违约金、赔偿、扣款和解除权是否重复叠加；
- 附件清单、条款编号、签署页和动态网页版本是否完整。

## 溯源输出格式

每条风险至少输出：

```json
{
  "source_file": "客户合同.docx",
  "page_no": 4,
  "clause_no": "6.4",
  "start_offset": 1234,
  "end_offset": 1378,
  "quote": "合同中的连续原文",
  "page_method": "rendered_pdf"
}
```

页码优先采用 Word/PDF 实际渲染结果；无法渲染时可使用 Word 最近一次分页标记，但必须保留 `page_method`，避免把估算页码当成确定页码。

## 泛化与回归样例

`1-客户版待偏离  脱敏.docx` 用作验收样例而不是规则模板。规则不得出现客户名、固定文件名或只适用于该文件的段落位置。金额算术、日期、单位异常和文件冲突检查适用于其他合同；叉车特有检查只由“租赁 + 我方出租方 + 叉车/特种设备”场景 Playbook 启用。

该样例至少应稳定命中：报价税额异常、技术参数数量级异常、期限届满、解除后无租金留用、税务责任叠加，以及运费、驻场、维修时限、旺季通知冲突。
